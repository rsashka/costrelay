# CostRelay

HTTP/HTTPS-прокси для OpenAI Chat Completions: маршрутизация по цене между
RouterAI и локальными OpenAI-compatible серверами, веб-панель, портал локальных
HTTP-сервисов, статистика и лимиты.

- Валюта итогов — только факт из отчёта провайдера (`usage`). Запрос без отчёта
  (оборванный поток) стоимости не выдумывает: его оценка по профилю модели
  показывается отдельно, в итог, суточные агрегаты и бюджеты не входит.
- Итоги «за всё время» — по суточным агрегатам (живут дольше журнала), сам журнал
  ограничен сроком хранения записей. Оценки, запись в кеш и сбросы кеша
  считаются одной формулой стоимости для живых запросов, панели и API.
- Единственная очередь провайдеров на модель по `weight RUB/M` — стоимость
  токенов плюс цена наблюдаемой задержки провайдера; живой запрос маршрут не
  пересчитывает, а берёт верх снимка очереди. Удерживаемый лидер и привязка
  сессии стоят первыми, порядок остальных офферов — по весу.
- Прежде чем уйти от текущего провайдера, прокси ждёт, пока это выгодно: цена
  уже потерянного времени сравнивается с разницей стоимости следующего оффера,
  а ожидание ограничено.
- Провайдер стабилен для беседы, пока это выгодно: привязка сессии удерживает
  провайдера, но снимается сразу, как только другой оффер дешевле на порог
  выгодности. Каждая смена логируется.
- Всплеск стоимости из-за смены провайдера записывается в журнал обязательно
  (`provider_switch_cache_loss`) с причиной и подробностями. Ошибка провайдера
  (сеть, таймаут, 429, 5xx, пустой ответ) повторяется у него же, пока ожидание
  выгодно, без записи тела на диск; каждая неудачная попытка видна в журнале
  (`retries`).
- Неработающий провайдер уходит из маршрута (запрос сразу идёт следующему),
  периодически проверяется и возвращается после успешных проверок; главная
  страница показывает сообщение «Провайдер не работает» с причиной.
- Панель: сводка за сутки, страница «Логи» (провайдеры и журнал запросов с
  фильтрами по дню, сессии, модели, провайдеру и важности), сравнение
  провайдеров, чёрный список, импорт статистики провайдеров (CSV). Ошибки и
  предупреждения текущих суток на главной ведут в журнал с готовым фильтром.
  Отдельная страница маршрутизации: текущий и предыдущий маршрут, все настройки
  алгоритма, сброс статистики кеша и предпросмотр весов на последних запросах:
  карточки профиля показывают токены и вклад в weight по сохранённым и ещё не
  сохранённым значениям, применение — только по кнопке сохранения.
- Лимиты на токен: rpm, tpm, параллелизм, сети, срок, суточный бюджет.
- Метрики Prometheus, захват тел запросов/ответов (опционально).

## Сборка

```bash
./scripts/bootstrap_deps.sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j"$(nproc)"
```

## Настройка

```bash
./build/costrelayd --init-config          # создать config/costrelay.yaml
$EDITOR config/costrelay.yaml             # секреты, модели, провайдеры
./build/costrelayd --config config/costrelay.yaml --check
```

- Параметры и допустимые значения описаны только в комментариях файла, который
  создаёт `--init-config`.
- Секреты (ключи провайдеров, токены, пароли) задаются ссылками `file:/путь` или
  `env:ИМЯ`; литералов в YAML нет. Пароль панели и токены создаются командами
  `--hash-password` и `--hash-token`.
- Относительные пути считаются от каталога файла конфигурации, а не от рабочего
  каталога процесса. `~/...` и абсолютные пути используются как есть.
- `listen` — локальный HTTP-листенер (loopback-агенты ходят по HTTP),
  `tls.listen` — HTTPS для локальной сети. Один порт на `0.0.0.0` и `127.0.0.1`
  одновременно занять нельзя, поэтому адреса в шаблоне разные.

## Запуск

```bash
./build/costrelayd --config config/costrelay.yaml
```

- Локальные агенты и сетевые клиенты: адреса и порты — из `proxy.listen` и
  `proxy.tls.listen` рабочего конфигурационного файла (сертификаты нужны только
  сетевым клиентам).
- Панель: `/panel` (после входа — `/`), логи — `/panel/stats`,
  сравнение провайдеров — `/panel/providers`.
- Метрики: `/metrics`, если не отключены в конфигурации.
- Портал локальных сервисов — `/<id>/` при включённом портале.
- Тела запросов не сохраняются, если не включён `capture`.

## Сервис при загрузке

```bash
sudo ./deploy/install-service.sh     # costrelayd + dsh-web + strata в multi-user.target
sudo ./dsh/install-service.sh        # только DSH (127.0.0.1:3080, меню /dsh/)
```

Скрипты ставят юниты systemd и `/etc/sudoers.d/costrelay-restart`, поэтому в
меню «Сервисы» доступен перезапуск. Если `costrelayd` уже запущен вручную,
остановите его: порты из `proxy.listen` и `proxy.tls.listen` должны быть
свободны. DSH читает `~/.dsh/profiles/<профиль>/cordis.patch.yml` на лету, а
`config/costrelay.yaml` — только при старте, поэтому меняйте их согласованно.

## TLS и доверие локальному УЦ

```bash
./scripts/gen_local_ca.sh            # корень (раз) и серверный сертификат
```

- `state/pki/ca.pem` (PEM) и `state/pki/ca.cer` (DER) — корень, раздаётся
  клиентам. Приватный ключ УЦ `state/pki/ca.key` с сервера не уходит.
- `state/tls/fullchain.pem` (leaf + корень) и `state/tls/server.key` — то, что
  указано в `proxy.tls`.
- SAN содержит только DNS-имена (`server`, `server.lan`, `server.local`,
  `localhost`) и не привязан к IP: адрес выдаёт DHCP, TLS проверяется по имени.

Корень нужно один раз добавить в доверенные на каждой машине-клиенте:

| ОС | Установка корня |
|----|-----------------|
| Debian / Ubuntu | `sudo cp ca.pem /usr/local/share/ca-certificates/costrelay-root-ca.crt && sudo update-ca-certificates` |
| RHEL / Fedora / Alma / Rocky | `sudo cp ca.pem /etc/pki/ca-trust/source/anchors/costrelay-root-ca.pem && sudo update-ca-trust extract` |
| Arch, любой `p11-kit` | `sudo trust anchor --store ca.pem` |
| Linux-скрипт | `sudo ./deploy/install-client-ca.sh ca.pem` |
| Windows | `certutil -addstore -f Root ca.cer` или двойной клик по `ca.cer` → «Корневые центры сертификации» |
| macOS | `sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain ca.pem` |
| iOS / Android | установить `ca.pem` как профиль (iOS) или «CA-сертификат» (Android) |
| Firefox | своё хранилище: «Настройки» → «Сертификаты» → «Просмотр» → «Импорт» |

Имя из SAN должно резолвиться (mDNS `server.local`, DNS `server.lan` или запись
в hosts): по IP TLS завершится ошибкой имени, и это ожидаемо. Проверка после
установки корня:

```bash
curl -v https://<хост-из-SAN>:<порт-из-proxy.tls.listen>/healthz          # 200 и «SSL certificate verify ok»
```

Сроки: корень — 10 лет, серверный сертификат — 5 лет. Сертификат перевыпускается
без переустановки корня (`./scripts/gen_local_ca.sh` и перезапуск `costrelayd`);
перевыпуск корня (`--force-ca`) ломает доверие и требует переустановки на всех
клиентах.

## Стабильность провайдера

- В запрос к RouterAI уходит один провайдер: смена на стороне внешнего
  обработчика невозможна, при отказе видна ошибка, а не скрытый переезд.
- Провайдер удерживается для беседы: очередь не дёргается на минимальных
  различиях в цене, а сессия остаётся на своём провайдере, пока тот допущен
  очередью.
- Любая вынужденная смена провайдера и всплеск стоимости из-за потери кеша
  записываются в журнал: причина, откуда и куда, во сколько раз дороже. Коды —
  `provider_affinity_rebind` и `provider_switch_cache_loss`, счётчик —
  `costrelay_route_cache_loss_total`.
- Ответ без вывода (нет текста, reasoning и вызова инструмента) — отказ
  провайдера: поток не уходит клиенту до первого содержательного фрагмента,
  поэтому запрос можно повторить или увести следующему по очереди. Отказ каждой
  попытки пишется предупреждением, остановка запроса — ошибкой.
- Провайдер с серией отказов уходит из маршрута, живой запрос сразу идёт
  следующему, а главная страница показывает «Провайдер не работает». Пока он вне
  маршрута, его проверяют минимальным запросом и возвращают после успешных
  проверок подряд.
- Пара (провайдер, модель) с серией запросов без попаданий в кеш уходит в
  чёрный список автоматически; статистику кеша можно сбросить на главной.
- Настройки стабильности — в блоке `routing` (см. комментарии `--init-config`).

## Команды

```text
--config FILE         запуск с FILE (по умолчанию config/costrelay.yaml)
--check               проверить конфигурацию и выйти
--init-config [FILE]  создать конфиг с комментариями
--force               перезаписать существующий конфиг при --init-config
--hash-password       Argon2id-хеш пароля панели
--hash-token [ID]     сгенерировать токен агента и sha256-хеш
--id NAME             id токена для --hash-token
--help, -h            справка
```
